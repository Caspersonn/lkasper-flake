# lkasper-flake

## Testing a host in a VM

Every NixOS host in this flake can boot as a throwaway QEMU VM on your
workstation. It runs that host's own configuration, but it doesn't touch the
real machine, your files or anything outside the VM.

```sh
nix run .#vm-kaito                     # boot kaito (keeps its disk between runs)
nix run .#vm-sakura -- --reset         # throw sakura's disk away and boot fresh
nix run .#vm-kaito -- --forward 8123:8123   # Home Assistant at http://127.0.0.1:8123
nix run .#vm-kaito -- --help
```

There is one app per host: `vm-sakura`, `vm-kaito`, `vm-neko`,
`vm-technative-casper`, `vm-gaming-casper`, `vm-personal-casper` and
`vm-server-casper`. `nix flake show` lists them.

### Options

| Option | Meaning |
|---|---|
| `--reset` | Delete this host's disk image first and boot fresh |
| `--ssh-port N` | Workstation port for SSH into the VM (default `2222`) |
| `--forward HOST:GUEST` | Forward TCP port `HOST` on the workstation to port `GUEST` in the VM; repeatable |
| `--headless` | No VM window; the console runs in your terminal |
| `-h`, `--help` | Show the options and the disk image path |
| `-- ARGS...` | Everything after `--` goes to QEMU unchanged |

To run two VMs at the same time, give one of them another SSH port, for example
`nix run .#vm-sakura -- --ssh-port 2223`.

### Getting in

- The console logs in as `casper` automatically. Desktop hosts log straight
  into GNOME (sakura) or Hyprland (the `*-casper` laptops and desktops).
- `sudo` needs no password inside the VM.
- SSH uses your normal key:
  `ssh -p 2222 -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null casper@127.0.0.1`
- Stop the VM with `sudo poweroff` inside it.

None of this applies to the real hosts; it all lives in
`virtualisation.vmVariant` (see `modules/nix/vm-testing.nix`).

### Where the state lives

Each host has one disk image at `~/.local/state/lkasper-vms/<host>.qcow2`
(`$XDG_STATE_HOME` is respected). Files you create in the VM survive a restart
until you use `--reset`. Images grow up to 20 GB each.

Clean up with:

```sh
rm ~/.local/state/lkasper-vms/*.qcow2
nix-collect-garbage
```

### Resources

VMs get 4 GB RAM, 4 cores and a 20 GB disk; kaito gets 8 GB. Run one heavy VM
at a time on a laptop. Server hosts (kaito, neko, server-casper) have no window;
desktop hosts open one unless you pass `--headless`.

### What is isolated

- **Network:** the VM sits behind QEMU's NAT. It has internet and DNS, but the
  LAN can't reach it, forwarded ports only listen on `127.0.0.1`, and new
  connections from the VM to your workstation (`10.0.2.2`) are rejected.
- **No secrets:** the VM has its own SSH host key, so agenix can't decrypt
  anything. Services that need a secret fail; `systemctl --failed` shows them
  (on kaito: AIOStreams, Mosquitto, Navidrome, Vaultwarden).
- **No outward identity:** Nebula, Tailscale and WireGuard are off, ACME never
  contacts Let's Encrypt (nginx uses self-signed certificates), and neko's
  scheduled hibernation is disabled.
- **Your files:** only the read-only Nix store is shared with the VM.

### What doesn't work

- Hardware: GPUs, Bluetooth, Wake-on-LAN, fingerprint readers, external disks.
- The bootloader and LUKS; the VM boots its kernel directly.
- Anything that needs a secret (see above), or files from your real home
  folder (on technative-casper, `linny-mcp` fails because its repo is missing).
- Your home-manager setup. It is a separate `casper@<host>` configuration, not
  part of the NixOS system, so the VM user starts with default settings
  (Hyprland shows its autogenerated config).
- neko and server-casper don't evaluate at the moment
  (`nextcloud-32.0.15` is marked insecure), so their VMs don't build either.
- server-casper is aarch64; on an x86_64 workstation it runs emulated and slow.
- The VM can still reach other LAN addresses through NAT, so don't add
  integrations that control real devices while testing.
